## 定位：Tier 5 与前三级的根本区别

```
Tier 1-3  在"内存读写"这件事上做文章
Tier 4    让"内存"本身变得可控（翻译层能力）
Tier 5    让 guest 能观测到的"一切"变得可控 —— 不只是内存
```

**Tier 4 的对象是内存，Tier 5 的对象是"guest 的整个观测面"。**

**技术前提已核实**：现有 VMEXIT 已实现 **35 种**，覆盖 Tier 5 全部所需基础：

```
CPUID / MSR / CR0-8(读+写) / EXCEPTION_{DB,DF,GP,NP,SS,UD} /
NPF / INTR / NMI / HLT / PAUSE / INVD / INVLPG / INVLPGA /
WBINVD / MONITOR / MWAIT / MWAIT_COND / RDTSC / RDTSCP /
VMMCALL / XSETBV / SHUTDOWN / AVIC_*
```

## ★★★★ 5.1 时间线控制（TSC / 时钟虚拟化）

### 这是什么

**控制 guest 看到的时间流速、时间点、甚至时间方向。**

```
guest 执行 RDTSC  →  我们不返回真实 TSC，而是返回我们计算的值

用途：
  ① 冻结时间（检测器看不到"操作耗时异常"）
  ② 加速/减速（让超时逻辑失效）
  ③ 回退（让 guest 以为时间倒流）
  ④ 一致性伪造（多个核的 TSC 完美同步，即使真实值有偏差）
```

### 为什么这是"狠"的

| 能力 | 宿主内核 |
|---|---|
| 读 TSC | 能（`__rdtsc`） |
| **控制 TSC 的值** | **不能** —— TSC 是硬件寄存器，宿主改不了 guest 的 |
| **对同一 guest 不同核返回不同 TSC** | **不能** |

### 用途

**用途 A：反时序检测**
```
检测器测量"某操作耗时" → 我们让它看到恒定的耗时
→ 无法通过时间差异发现虚拟化或异常
```

**用途 B：超时逻辑欺骗**
```
游戏的"心跳超时" / "反作弊轮询间隔" → 我们控制时间流速
→ 让它永远不超时，或永远认为刚检查过
```

**用途 C：时间戳一致性**
```
多核 TSC 有微小偏差（正常）→ 我们让它们完美一致
→ 检测"TSC 偏差"的反虚拟机手段失效
```

### 已实现的基础

```
✅ SVM_EXIT_RDTSC / SVM_EXIT_RDTSCP 已在 vmexit.c 处理
✅ 现有 INTERCEPT_RDTSC 已在 206 主线启用
→ 只需把"透传真实值"改为"返回计算值"
```

**风险**：中。TSC 被大量代码依赖（调度、超时、性能计数），改错会导致 guest 行为异常。

## ★★★★ 5.2 指令流重定向（Instruction Stream Redirection）

### 这是什么

**guest 执行了指令 A，但实际效果是指令 B** —— 不修改任何内存。

```
guest:  mov eax, 1        →  我们让它实际执行:  mov eax, 0
guest:  call func_a       →  我们让它实际调用:  func_b
guest:  cmp eax, 5        →  我们让它变成:     cmp eax, 5 但结果反转
```

### 机制

```
① 拦截指令执行（CPUID/MSR/特定指令的 VMEXIT）
② 读取 VMCB 里的 GuestRip / 寄存器状态
③ 修改寄存器状态 / NRip / 甚至伪造指令效果
④ 返回 guest，它以为自己的指令执行了
```

### 为什么这是"狠"的

| 能力 | 宿主内核 |
|---|---|
| Hook 函数（改代码） | 能（但**可被检测**：代码完整性校验） |
| **不改任何内存就改变行为** | **不能** |
| **对代码完整性校验完全免疫** | **不能** |

### 用途

**用途 A：绕过完整性校验的 hook**
```
传统 hook：改函数头 5 字节 → 完整性校验发现
我们的方式：不改内存，只在 VMEXIT 里改寄存器
→ 代码校验 100% 通过，但行为已被改变
```

**用途 B：条件行为**
```
只在特定条件（特定调用者、特定参数）下重定向
→ 极其精准，不留痕
```

**风险**：**高**。指令级语义复杂，改错会导致 guest 崩溃。建议限定在白名单指令（CPUID/MSR/RDTSC 等已有拦截的）。

## ★★★★ 5.3 系统调用 / 中断虚拟化（Syscall & Interrupt Virtualization）

### 这是什么

**拦截 guest 的系统调用、中断、异常，按需返回伪造结果。**

```
guest: syscall NtQueryInformationProcess
  → 我们拦截（或拦截其内部的 CPUID/MSR）
  → 返回伪造的进程信息
  → guest 认为查询成功了
```

### 为什么这是"狠"的

| 能力 | 宿主内核 |
|---|---|
| Hook SSDT | 能（但可被检测：SSDT 完整性、PatchGuard） |
| **在 SSDT 之下拦截** | **不能** |
| **对 PatchGuard 免疫** | **不能** |

**关键**：PatchGuard 保护的是**宿主内核**的结构。
我们的拦截在**guest 的虚拟化边界**上，**PatchGuard 看不到**。

### 用途

**用途 A：信息伪装**
```
检测器查询"进程列表" / "模块列表" / "内存区域"
→ 我们返回过滤后的结果（隐藏我们的痕迹）
```

**用途 B：异常抑制**
```
guest 触发异常 → 我们判断"是否应该让它看到"
→ 检测器探测的异常被静默处理
```

**已实现的基础**：
```
✅ SVM_EXIT_EXCEPTION_{DB,DF,GP,NP,SS,UD} 已实现
✅ SVM_EXIT_INTR / SVM_EXIT_NMI 已实现
✅ SVM_EXIT_VMMCALL 已实现
```

**风险**：中高。异常语义复杂（尤其 #DB / #GP），误处理会导致 guest 崩溃。

## ★★★★ 5.4 硬件视图伪造（Hardware Topology Faking）

### 这是什么

**guest 看到的 CPU / 硬件拓扑是伪造的。**

```
guest 执行 CPUID  →  我们返回定制的 CPU 信息
```

### 为什么这是"狠"的

| 能力 | 宿主内核 |
|---|---|
| 读 CPUID | 能 |
| **改 CPUID 的返回值** | **不能** —— CPUID 是硬件指令 |
| **对同一个 guest 的不同进程返回不同 CPUID** | **不能** |

### 用途

**用途 A：反虚拟机检测对抗**
```
检测器查 CPUID 找 hypervisor 位 / 厂商字符串
→ 我们返回"裸机"特征
（现有代码已在处理 CPUID，只需扩展）
```

**用途 B：特征伪装**
```
让目标进程看到特定的 CPU 型号/特性
→ 影响它的代码路径选择（如 SIMD 分支）
```

**用途 C：按进程区分**
```
不同进程看到不同的硬件 → 极其罕见的检测手段
```

**已实现的基础**：
```
✅ SVM_EXIT_CPUID 已实现
✅ 现有代码已有 CPUID leaf 'SSV1'(0x41414142) 用于内部通信
→ 扩展为完整的 CPUID 虚拟化
```

**风险**：低-中。CPUID 语义清晰，且已有实现。

## ★★★★ 5.5 性能计数器伪造（PMC / MSR Virtualization）

### 这是什么

**guest 读取的性能计数器（PMU）、MSR 是伪造的。**

```
guest: rdmsr IA32_PERF_GLOBAL_CTRL  →  我们返回定制值
guest: rdpmc                         →  我们返回伪造计数
```

### 为什么这是"狠"的

| 能力 | 宿主内核 |
|---|---|
| 读 MSR/PMC | 能 |
| **改它们的值** | **不能** |
| **按 guest 意图区分** | **不能** |

### 用途

**用途 A：侧信道防护**
```
检测器用 PMC 做侧信道分析 → 我们返回噪声/恒定值
```

**用途 B：性能特征伪装**
```
让目标进程的性能测量"看起来正常"
```

**已实现的基础**：
```
✅ SVM_EXIT_MSR 已实现
✅ SVM_EXIT_XSETBV 已实现（XCR0，SIMD 状态）
✅ SVM_EXIT_INVD / WBINVD / INVLPG / INVLPGA 已实现
```

**风险**：中。MSR 种类多，需按白名单处理。

## ★★★★ 5.6 执行轨迹控制（Execution Tracing & Replay）

### 这是什么

**完整记录 guest 的执行轨迹**（指令级 / 内存访问级），或**重放**某段轨迹。

```
记录：每条指令的 RIP、每次内存访问的地址和值、每次分支
重放：在隔离环境里重放，观察行为差异
```

### 为什么这是"狠"的

| 能力 | 宿主内核 |
|---|---|
| ETW / 内核 trace | 能（但**有开销、可被检测**、且看不到 guest 内部） |
| **零开销的完整轨迹** | **不能** |
| **目标无感知** | **不能**（ETW 会设置标志位） |

### 用途

**用途 A：行为分析**
```
目标进程对敏感数据的所有访问 → 完整图谱
（NPF 天然带 RIP + CR3 + 访问类型）
```

**用途 B：崩溃复现**
```
记录到崩溃前的完整轨迹 → 精确复现
```

**用途 C：条件触发**
```
"当且仅当某条指令读某地址"时执行动作
→ 精准断点，无需 int3
```

**已实现的基础**：
```
✅ NPF 已带 GuestRip + 访问类型（读/写/执行）
✅ 遥测环（npf/deny/vr/dbg 各 32 条）已存在
→ 扩展为完整的轨迹缓冲
```

**风险**：低-中。主要是性能与缓冲管理。

## ★★★ 5.7 虚拟设备与 I/O 控制（Virtual Device & I/O）

### 这是什么

**guest 的所有 I/O（端口、MMIO、设备寄存器）都经过我们。**

```
guest: in/out 指令        →  我们拦截并返回定制值
guest: 访问 MMIO 区域     →  我们拦截（NPF）
```

### 为什么这是"狠"的

| 能力 | 宿主内核 |
|---|---|
| 过滤 I/O | 能（但需驱动，可被检测） |
| **对 guest 完全透明** | **不能** |

### 用途

**用途 A：设备特征伪装**
```
检测器查设备指纹（磁盘序列号、网卡 MAC、显卡 ID）
→ 我们返回定制值
```

**用途 B：I/O 行为分析**
```
记录 guest 的所有 I/O → 行为画像
```

**已实现的基础**：
```
✅ SVM_EXIT_INVD / WBINVD / INVLPG / INVLPGA 已实现
✅ NPF 可拦截 MMIO 访问
⚠️ 端口 I/O 拦截需确认 VMCB 配置（INTERCEPT_IOIO_PROT）
```

**风险**：中高。I/O 语义复杂，误拦截会导致设备驱动异常。

## ★★★★ 5.8 多核一致性操纵（Multi-Core Coherence Control）

### 这是什么

**控制多个 vCPU 之间的可见性与顺序。**

```
CPU0 写地址 X  →  CPU1 读到的是"旧值"（而不是新值）
→ 违反正常的内存一致性模型，但可控
```

### 为什么这是"狠"的

| 能力 | 宿主内核 |
|---|---|
| 内存屏障 | 能（只能保证顺序，不能违反） |
| **故意违反一致性** | **不能** |
| **按核区分可见性** | **不能** |

### 用途

**用途 A：竞态利用**
```
让多线程检测逻辑看到不一致的状态 → 它的判断失效
```

**用途 B：原子性破坏**
```
让"看似原子"的操作在特定核上不原子
```

**风险**：**高**。会导致难以调试的 guest 崩溃。

## ★★★★★ 5.9 观测面完全控制（Total Observability Control）—— 终极

### 这是什么

**把 Tier 4 + Tier 5 全部组合** —— guest 能观测到的**一切**都是我们给的。

```
guest 看到的：
  内存    → Tier 4（视图分裂）
  时间    → Tier 5.1（TSC 控制）
  指令    → Tier 5.2（指令流重定向）
  系统调用 → Tier 5.3（syscall 虚拟化）
  硬件    → Tier 5.4（CPUID 伪造）
  性能    → Tier 5.5（PMC 伪造）
  轨迹    → Tier 5.6（轨迹控制）
  I/O     → Tier 5.7（设备虚拟化）
  一致性  → Tier 5.8（多核操纵）
```

**这是"完全虚拟化"的终极形态** —— 不是"隐藏我们的存在"，
而是"**guest 活在我们为它构建的现实里**"。

### 用途

**用途 A：完美沙箱**
```
让目标进程在"它以为是真实环境"里运行，实际完全受控
```

**用途 B：行为研究**
```
观察目标在受控条件下的完整行为
```

**用途 C：对抗一切检测**
```
检测器能观测的每个面都是我们给的
→ 它无法找到任何"异常"，因为我们定义了什么算正常
```

**风险**：**极高**。这是全系统的复杂度，任何一处出错都导致 guest 崩溃。
